ARCHITECTURE (CURRENT)

  User Query (UI/CLI)
          │
          ▼
    run_ingest()                                    [app/rag/ingest.py]
      ├─ load_schema_docs()
      ├─ compute_schema_hash()
      ├─ has_schema_changed()
      └─ generate/store embeddings if changed
          │
          ▼
  get_retrieval_context(question)                   [app/rag/context_service.py]
      ├─ retrieve_relevant_docs(question)           [app/rag/retriever.py]
      └─ build_context(docs)
          │
          ▼
  generate_sql(question, context)                   [app/llm/generate_sql.py]
      ├─ plan_query(question)                       [app/llm/planner.py]
      ├─ match_kpi(question, plan)                  [app/llm/kpi_matcher.py]
      ├─ resolve_metric(question)                   [app/llm/metric_resolver.py]
      ├─ compose_sql_user_prompt(user_query, context, plan_block, kpi_block, metric_block) [app/llm/prompts.py]
      ├─ blocked KPI? return blocked_kpi_message SQL
      └─ OpenAI SQL generation
          │
          ▼
  validate_sql() + enforce_limit()                  [app/db/validator.py]
          │
          ▼
  run_query(sql)                                    [app/db/query_runner.py]
          │
          ├── success → explain_results(question, sql, results) [app/llm/explain_results.py]
          │
          └── error   → fix_sql(user_query, sql, error, context)
                        ├─ planner + KPI + metric steps reused
                        └─ corrected SQL retry


OFFLINE EVAL (CURRENT)

  app/eval/planner_kpi_cases.json
          │
          ▼
  app/eval/run_planner_kpi_eval.py
      ├─ validates planner intent + time grain
      ├─ validates KPI matched/fallback behavior
      └─ validates blocked KPI routing expectations
